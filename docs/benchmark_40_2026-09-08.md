# Structured v3: 20 NExT-QA + 20 EgoSchema

Run date: 8 September 2026, Australia/Melbourne. This is a live evaluation of the
local experimental `structured-evidence-v3` profile, using
`gpt-4.1-mini-2025-04-14`. The public Space and its `clean` profile were not changed.

## Outcome

The current structured pipeline is not reliable enough: 18 of 40 analyses
completed and 13 returned the reference answer. Another 22 stopped on validation
errors. All 613 inference requests returned HTTP 200; this was not an API outage.

| Dataset | Attempted | Completed | Correct / attempted | Accuracy | Stopped |
| --- | ---: | ---: | ---: | ---: | ---: |
| NExT-QA validation | 20 | 7 | 6/20 | 30% | 13 |
| EgoSchema public labeled subset | 20 | 11 | 7/20 | 35% | 9 |
| Total | 40 | 18 | 13/40 | 32.5% | 22 |

Completed means the answer and review stages finished, not that review accepted
the reasoning. One completed EgoSchema analysis abstained. Failed analyses and
abstentions count incorrect. Correctness uses the final selected option against
the official label; intermediate choices do not replace failed final outputs.
Only one completed result received an accepted review; it was correct. The other
17 completed results remained unverified.

This is a small, app-eligible sample, not a full benchmark result. It is also not
a paired comparison with earlier prompt profiles or another model.

## What failed

Nineteen failures occurred in the structured Answer stage; the other three were
in evidence inspection, preliminary choice selection, and the tool agent.
Offline replay against the frozen validators identified these terminal errors:

| Final validation failure | Cases |
| --- | ---: |
| A claim did not connect to an answer or option root | 10 |
| A planned evidence need did not reach an answer claim or explicit limitation | 6 |
| The selected option was marked unsupported | 2 |
| A claim had no resolved frame provenance | 1 |
| Inspection cited an unknown frame ID | 1 |
| Choice selection returned text outside the supplied options | 1 |
| Whole-video retrieval omitted the required overview | 1 |

Thus 16 of 22 stops were claim-graph or planned-need coverage errors. These
categories describe the final error reported, not every defect in a response.

The retained intermediate predictions show where answers were lost:

| Diagnostic only | NExT-QA | EgoSchema | Total |
| --- | ---: | ---: | ---: |
| Accepted preliminary choices matching the reference | 16/18 | 13/19 | 29/37 |
| Last raw structured answers matching the reference | 13/18 | 11/19 | 24/37 |

These denominators include only cases that produced the corresponding output.
They are not end-to-end accuracy or proof of visually supported reasoning.
Among the 19 Answer-stage failures, 11 last raw drafts selected the reference
answer, seven abstained, and one selected another option.

Concrete examples from the saved traces:

- `nextqa-4984417707-q0`: the raw answer selected the reference, “trying to kick
  ball,” but a contextual claim was disconnected from the answer roots. The
  validator rejected the graph.
- `nextqa-5116088152-q7`: the first answer selected “grab the banana” but omitted
  the adult-pointing need. Repair returned an abstention covering that need but
  dropped the baby-reaction need, so it still failed. The inspector had also
  marked adult pointing unresolved; this was not just harmless formatting.
- `nextqa-2697214342-q9`: choice selection returned “three” twice, although that
  was not a supplied option. The reference was “four.”
- In the EgoSchema cable and sewing cases, review requested revision of an
  `unsupported` alternative while its explanation itself said there was no
  evidence for that alternative. This is an apparent status/reason inconsistency,
  not proof of the model's internal reasoning or the depicted actions.

The priority suggested by this run is reliable answer delivery and targeted
repair of cross-agent records, especially claim connections, need coverage, and
review semantics. It does not justify adding more agents or claiming that prompt
changes can eliminate perception errors. No fixes or prompt changes were made
during or after this evaluation.

## Latency and cost

Two local workers ran hosted inference with fresh, isolated video indexes.
Index timing excludes local preparation. QA includes retrieval, evidence
inspection, answer generation, and review; its timing below covers completed
analyses only. Total timing covers all attempted cases, including early stops.

| Metric | NExT-QA | EgoSchema |
| --- | ---: | ---: |
| Median cold indexing | 6.14 s | 15.79 s |
| Median QA, completed analyses | 43.88 s | 56.49 s |
| Median total, all attempts | 48.00 s | 70.55 s |
| HTTP requests | 246 | 367 |
| Estimated API cost | $0.2998 | $0.4609 |

The run took approximately 20 minutes 5 seconds, excluding setup and audit.
These are local evaluation timings, not public-site queue latency. Completed
analyses selected an average of 34.96 seconds of NExT-QA evidence and 52.73
seconds of EgoSchema evidence; indexing still sampled across each video.

Provider-reported usage was 1,693,384 input tokens, including 293,120 cached input
tokens, and 107,082 output tokens. Estimated API cost was **$0.7607488 USD**.
The OpenAI Docs skill informed the accounting: reported usage was valued at
$0.40/million uncached input, $0.10/million cached input, and $1.60/million output
using the [official GPT-4.1 mini pricing](https://developers.openai.com/api/docs/models/gpt-4.1-mini).
This estimate is not an account invoice and excludes local infrastructure.

There were 37 format-repair calls and 20 answer-revision calls, included in these
totals. All usage was known; no reservations or ambiguous charges remained. The
runner's $4 budget was not reached. All 40 allowed sessions were consumed, so
this batch is closed; the unused dollar allowance does not permit reruns.

## Method and reproducibility

- Seed `20260908`; independently shuffle sorted official question IDs, taking
  the first 20 eligible questions with unique videos per dataset. No label or
  question-type stratification.
- NExT-QA uses official `val.csv`; EgoSchema joins `questions.json` only to the
  500 public labels in `subset_answers.json`. No pseudo-labels or descriptions
  were used as references.
- Preserve original questions, five choices, and choice order. Reference labels
  are read only for scoring after inference and are absent from model inputs.
- Exclude videos identified in prior local examples, evaluations, tests, and
  project text: four NExT-QA and three EgoSchema video IDs. The manifest records
  exclusions and their sources; this does not establish model-training holdout.
- Apply the demo's media and input limits: at most 180 seconds, 100 MiB, 3840-pixel
  maximum dimension, and 300 characters per option. Two shuffled NExT-QA rows
  exceeded the duration limit; two EgoSchema questions exceeded option length.
- Use fresh caption/vector caches and frozen source hashes for every case. Keep
  native bounded format repair and one answer revision. Never rerun failures or
  substitute a draft for the final pipeline result.

An independent audit matched official labels and option order, frozen source
hashes, all 613 actual request/schema/image payload hashes, frame provenance,
raw outputs, and budget records. Original run records were not rewritten.
Artifact integrity does not imply benchmark success. No independent visual
grading was performed; perception mistakes remain outside this contract audit.

# SVP-inspired agent examples — 7 September 2026

This is a development regression of planning/tool compilation, not a new held-out
video-answer benchmark. The [system contract](qa_planning_and_tools.md) describes
the implementation and its differences from StructuredVP.

## Adaptation

- Independently authored Question → Plan → ToolProgram pairs, not copied SVP
  benchmark questions, expected answers, or unsupported APIs.
- Three balanced planner examples. The compiler selects one scope/direction-matched
  example, or two for mixed before/after dependencies. No extra LLM selection call.
- Question/choices-only planning: no current-video captions to prime a predicted
  outcome. The compiler alone receives those fallible search hints; global hints
  are grouped by actual scene-midpoint thirds.
- Hard whole-video contract: three independent positional locates, no relations,
  exactly those three outputs inspected. Distinct temporal representatives must
  fit the actual top-k and three-window/60-second budgets before answering.
- Actual prompt-example version/IDs and all raw validation attempts remain in the
  trace. New coverage details show selected spans, not merely early/middle/late tags.

The visual inspector, answerer, and reviewer do not receive fictional examples.
Qwen3-VL-8B-Instruct, frame budgets, bounded repair/correction policy, and the paid
Space's hardware/sleep policy are not changed by this prompting work.

## What real model inspection caught

Candidate V1 passed all five structural checks with zero JSON repairs, but its
outputs were not good enough:

- Sofa: it predicted placing the gift on a cushion and treated that as sufficient
  explanation of the movement, instead of seeking the subsequent interaction.
- Kitchen: its queries used the first three cached scenes despite claiming
  beginning/middle/end positions across a nine-window video.

V2 separated the planner's inputs from the cached timeline and explicitly grouped
the compiler's global hints. Sofa then asked what happens to the same present
after arrival; kitchen queries used their correct temporal groups. V3 removes a
workbench-specific word from the example rationale that the model had copied into
an unrelated kitchen plan. Earlier outputs are preserved, not overwritten.

These observations motivate the changes, but do not isolate the effect of ICL
from the accompanying input/rule changes. There is no instruction-only accuracy
ablation here and no claim of improved benchmark accuracy.

## Evaluation setup

The local harness executes the real `LivePipeline.qa` planner and compiler and
stops after the second yield. It uses Qwen3-VL-8B-Instruct BF16/SDPA, pinned revision
`0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`, on an otherwise idle A100 40 GB.
Local Python 3.10/Transformers 4.57 differs from the hosted environment; an isolated
StrEnum shim and the processor's text-only chat template support this local test.
These timings are not L4 end-to-end latency measurements.

The five frozen cases are sofa multiple-choice, kitchen multiple-choice, kitchen
open-ended, and two clearly synthetic contract cases (an independent attribute
and a preceding-cause query). Three cases use real saved captions from two existing
library videos. Saved answers/reference labels and previous verification are
excluded from model inputs. The synthetic cases measure structure, not vision.

All original prompts, raw generations, token/timing records, model/source identities,
and validation outcomes are under
[the evaluation artifacts](../artifacts/evaluation/agent_icl_2026-09-07/).
`paired_v1_actual`, `paired_v2_actual`, and `paired_v3_actual` identify the prompt
candidates. Separate CPU retrieval checks execute the final actual programs;
they do not generate video answers.

## Final V3 results

All five planner/compiler pairs passed their structural contracts without a repair.
Manual inspection of the actual outputs also checked the semantic failures above:

| Case | Planner/compiler seconds | Observed behavior |
| --- | ---: | --- |
| Sofa MC | 16.285 | Unknown post-arrival same-present interaction; both locates and `after` result inspected |
| Kitchen MC | 15.588 | Three independent, period-matched locates; no relations |
| Kitchen open-ended | 15.850 | Same three-period strategy without choices; no relations |
| Synthetic independent attribute | 10.015 | One need, one locate, no relation; no color guessed |
| Synthetic preceding cause | 15.413 | Event anchor and preceding-condition need; `before` result inspected |

Actual planner inputs were 1,518–1,564 tokens; compiler inputs were 1,875–2,560.
The maximum ordinary-English stress fixture, including two directional examples,
repair text, schema, chat wrapper, and reserved output, was 5,101 tokens. These
stress fixtures are not an exhaustive worst case over possible user text.
See the [final semantic review](../artifacts/evaluation/agent_icl_2026-09-07/paired_v3_review.md).

The full automated suite passed **444 tests** and Ruff. Local model processes
were stopped after evaluation; no local GPU service or keep-alive was left running.
No fresh image-backed QA accuracy measurement was performed in this change.

The [CPU retrieval checks](../artifacts/evaluation/agent_icl_2026-09-07/paired_v3_retrieval/summary.json)
also passed for the three real-caption cases, using newly computed MiniLM scene
and query embeddings and the actual V3-generated programs:

- Kitchen MC and open-ended both selected scenes 0, 4, 7: 0–20s, 80–100s,
  140–160s. Three distinct thirds, 60 seconds total, zero relations.
- Sofa selected scenes 1, 2, 3: approximately 18–36s, 36–54s, 54–72s.
  `l1` anchors scene 1; `r1` ranks scene 2 first as a strict-after candidate.
  The initial scene 0 is not selected, and the later interaction remains included.

Per-case CPU embedding plus retrieval took 0.069–0.079 seconds, excluding a
7.198-second one-time local encoder setup. Full input vectors, cosine hits,
programs, spans, and source hashes are retained. These are real retrieval results,
not proof that sampled images will support the final answer.

## Context and safety checks

Real prompt/schema/chat tokens are counted, including output reservation and
explicit tokenizer-only repair stress fixtures. Ordinary English fixtures with
the maximum allowed question/choice/caption lengths fit within 8192 tokens.
Token-dense text can exceed that limit despite satisfying character limits; the
existing token-aware guard rejects it before generation instead of truncating
evidence or increasing GPU memory use.

Tests cover valid paired demonstrations, scope/direction routing, example/current
task separation, planner caption isolation, exact midpoint grouping, rejection and
visible repair of the user's two-relations global program, missing-period failure
before visual QA, budget/top-k behavior, and unchanged local dependencies.

## Reproduce locally

The harness defaults to tokenizer-only. Actual local generation requires `--run`;
it refuses an existing output directory and checks that the selected GPU is idle.

```bash
/vast/s224013995/videomasys-vllm/bin/python scripts/evaluate_agent_icl.py \
  --output-dir artifacts/evaluation/agent_icl_2026-09-07/NEW_RUN \
  --run --gpu 2
```

No Hugging Face app requests or paid inference are used by this harness. Source,
examples, and the existing public video library are deployable; evaluation reports,
test fixtures, reference datasets, and local artifacts are not in the deployment
allowlist.
